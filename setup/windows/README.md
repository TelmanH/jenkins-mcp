# Company setup: Windows + VS Code GitHub Copilot

Everything you need to use the Jenkins MCP server at work. Takes about 10 minutes.
Developers who want to change or test the server: see [tests/README.md](../../tests/README.md) (`setup.ps1 -Dev`).

## What you need

- Windows with **Python 3.10 or newer** (`python --version`)
- **VS Code** with **GitHub Copilot** (Copilot Chat must offer **Agent** mode)
- Network access to your Jenkins (company network or VPN)
- A Jenkins **API token**: Jenkins -> your name (top right) -> *Security* -> *API Token* -> *Add new token*

## 1. Install

Open PowerShell in the project folder and run:

```powershell
powershell -ExecutionPolicy Bypass -File setup\windows\setup.ps1
```

Options when needed:

```powershell
# a specific Python and/or the company proxy (pip downloads packages)
powershell -ExecutionPolicy Bypass -File setup\windows\setup.ps1 -Python "C:\Program Files\Python311\python.exe" -Proxy "http://proxy.example.com:80"
```

The script creates `.venv`, installs the server, creates `config\jenkins_instances.yaml` and
`config\.env` from the templates, and writes `.vscode\mcp.json` with one token prompt per Jenkins
instance. Running it again is safe: your config files are kept.

> Untested on a real Windows machine so far: please report the script's output if a step fails.

## 2. Configure

**`config\jenkins_instances.yaml`**: your Jenkins servers. The name (`main` below) is your choice.

```yaml
default: main
instances:
  main:
    url: https://jenkins.your-company.example/
```

If the connection fails with a TLS/certificate error (internal CA), ask IT for the CA certificate as a
PEM file, put it into `certs\internal-ca.pem` and add `ca_bundle: certs/internal-ca.pem` under
`defaults:`. Last resort: `verify_tls: false`.

After editing the yaml (new or renamed instance), **run `setup.ps1` again**, so that `.vscode\mcp.json`
gets a token prompt for every instance.

**`config\.env`**: only the **user** per instance, named after the instance in upper case:

```
JENKINS_MAIN_USER=your-user-id
```

The **API token** is not stored in a file: VS Code asks for it once per instance when the server starts and
keeps it in its secure storage. `list_instances` shows `token: from the environment` for those.

Prefer a file? Run `setup.ps1 -TokensInEnvFile` and put `JENKINS_MAIN_TOKEN=...` into `config\.env`.
Never commit `config\.env`; it is already in `.gitignore`.

**Proxy:** `-Proxy` of the setup script is only for pip. If the Jenkins servers must (or must not) go through
the company proxy, set `proxy:` per instance in the yaml (`proxy: none` = direct, ignores `HTTPS_PROXY`).

## 3. Connect VS Code Copilot

1. Open the **project folder** in VS Code (File -> Open Folder). The server is defined in `.vscode\mcp.json`
   (generated by the setup script, not committed).
2. `Ctrl+Shift+P` -> **MCP: List Servers** -> `jenkins` -> **Start**. VS Code asks for the API token of
   each instance (input hidden). It should then show *Running*.
3. Open Copilot Chat, switch to **Agent** mode and check that the Jenkins tools are enabled
   (tools icon in the chat input).
4. Ask: **"list_instances with check_connection"**. Expected: `status: ok, Jenkins <version>`.

## 4. Use it

- *"Why did https://jenkins.your-company.example/job/app/job/deploy/123/ fail?"* (paste any build URL)
- *"What failed in the last 24 hours?"*
- Prompts: type `/` in the chat and pick `mcp.jenkins.analyse_build` or `mcp.jenkins.document_session`.

More examples: [docs/USER_GUIDE.md](../../docs/USER_GUIDE.md).

## Troubleshooting

| Symptom | Fix |
|---|---|
| `jenkins` not in *MCP: List Servers* | You opened a sub-folder. Open the project folder that contains `.vscode\mcp.json` |
| Server does not start | Run the setup script again; check that `.venv\Scripts\jenkins-mcp.exe` exists. *MCP: List Servers* -> jenkins -> **Show Output** shows the error |
| `JENKINS_MAIN_TOKEN is not set` | The token prompt was cancelled or the instance has no prompt: run `setup.ps1` again, restart the server and enter the token (or put it into `config\.env` and ask *"list_instances reload_config=true"*) |
| Wrong or expired token entered | Change the input `id` of that instance in `.vscode\mcp.json` (e.g. `jenkins-main-token` -> `jenkins-main-token-2`, both places) and restart the server: VS Code asks again. How to edit or delete a stored value in place is not documented by VS Code; look for MCP commands in `Ctrl+Shift+P` of your version |
| `Authentication failed (401)` | Use an API token, not your password |
| `TLS verification failed` | Set `ca_bundle` (see step 2) |
| `Cannot connect` | VPN / proxy / URL |

After changing `config\` files you do not need to restart: ask *"list_instances reload_config=true"*
(a token entered in VS Code always wins over `config\.env`). Exception: a new instance needs `setup.ps1`
again and a server restart, for its token prompt.

Slow first start? Measure it: `Measure-Command { .venv\Scripts\python.exe -c "import jenkins_mcp.main" }`
(about 0.3 s on a Mac).

## Update to a new version

Replace the project files (keep `config\` and `knowledge\`), run `setup\windows\setup.ps1` again, then
in VS Code: *MCP: List Servers* -> jenkins -> **Restart**.
